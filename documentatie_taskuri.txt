ETAPA 2 - CSS, schema cromatica si layout responsive
==================================================

1) Schema cromatica
- Culoare de baza aleasa: verde petrol #2f6f63.
- Schema folosita in CSS:
  - #2f6f63 - culoare principala, folosita pentru zone importante si taburi.
  - #17443e - varianta inchisa pentru header, footer, text accentuat si contrast.
  - #8fc9b5 - verde menta pentru accente calme si borduri secundare.
  - #d99b32 - accent amber pentru highlight-uri si elemente care trebuie observate.
  - #f3d9a2 - accent deschis pentru hover si suprafete calde.
  - #f6f2e8 - fundal cald al paginii.
  - #ffffff si #e7f3ee - suprafete pentru zone de continut.
- Motivatie: tema 4Pets are nevoie de o atmosfera de incredere, calm si grija. Verdele petrol si verdele menta sugereaza sanatate, siguranta si echilibru, potrivite pentru produse de ingrijire animale. Accentul amber adauga energie si caldura fara sa aglomereze vizual pagina.
- Variabilele de culoare sunt definite in selectorul body din resurse/css/style.css si sunt folosite in restul CSS-ului prin var(...).

2) Layout responsive
- Main-ul paginii foloseste CSS Grid cu grid-template-areas.
- Pe ecran mare, zonele sunt organizate dupa harta ceruta: zona 1 pe toata latimea, zona 2 in stanga sus, zona 8 in dreapta pe mai multe randuri, iar zonele 3, 5, 6, 4 si 7 completeaza partea inferioara.
- Pe ecran mediu, layoutul trece la doua coloane.\
- Pe ecran mic, layoutul trece la o singura coloana, fara scrollbar orizontal pe viewport.
- Font-size-ul html scade de la ecran mare la mediu si mic, iar body are tranzitie pentru schimbarea dimensiunii textului.
- Principii de design folosite: ierarhie vizuala prin zona 1 mai ampla, contrast intre header/footer si continut, proximitate prin gruparea zonelor similare, aliniere prin grid, consistenta prin aceleasi variabile de spacing si padding.

3) Design rudimentar
- Spatierea laterala a paginii este controlata prin variabila --spatiere-pagina si scade pe ecran mediu si mic.
- Gap-ul gridului este controlat prin --spatiere-grid si scade responsive.
- Zonele sunt izolate vizual prin background diferit, border, border-radius si box-shadow.
- Padding-ul zonelor este controlat prin --padding-zona.
- Elementele media au width in procente, min-width si max-width, ajustate pe ecran mic.

4) Iconuri si font extern
- Font extern: Nunito prin Google Fonts.
- Icon static Font Awesome: labuta din zona de prezentare.
- Icon animat Font Awesome: osul din zona de anunturi, animat discret pe ecrane mari/medii.

5) Stilizare tabel
- Tabelul are caption pozitionat sub tabel prin caption-side: bottom.
- Borderele dintre randuri alterneaza culorile prin pseudoclase nth-child.
- Borderele interioare au 1px, iar borderul exterior este inset si are grosime peste 5px.
- La hover pe rand apare gradual un outline de culoare transparenta cu alpha 0.7, cu tranzitie de 0.5s.
- Pe ecrane mici si medii, containerul tabelului permite scroll orizontal doar pentru tabel.

6) Stilizare taburi iframe
- Linkurile iframe sunt grupate in containerul taburi-iframe, pe care este aplicat display:flex.
- Taburile sunt plasate langa iframe, cu forma de butoane lipite, border, fundal si tranzitie.
- Efectul vizual urmareste animatia din exemplu: la hover tabul se lungeste spre dreapta si isi schimba culoarea, iar culorile sunt adaptate schemei cromatice a site-ului 4Pets.

7) Link top
- Linkul catre inceputul paginii este fix in dreapta jos.
- Nu foloseste imagini; forma rotunda si sageata sunt realizate din CSS si caracterul ↑.
- Butonul are opacity subunitar si devine opac la hover.
- Borderul este impartit vizual pe laturi deschise si inchise, are box-shadow intern, iar la hover cercul se roteste.
- Sageata ramane nemiscata deoarece rotirea este aplicata doar cercului decorativ, iar efectul de blur/text-shadow dispare la hover.
- Tooltipul apare la hover prin pseudo-element CSS.

8) Bonusuri
- Reset CSS in fisier separat: resurse/css/reset.css.
- Formula MathML are stilizare diferita pe identificatori si numere in resurse/css/style.css.

ETAPA 3 - SASS si meniu derulant responsive
==================================================

Fisiere principale: views/pagini/index.ejs, resurse/css/menu.scss, resurse/css/menu.css

1) Structura HTML a meniului
- Meniul este implementat in header, in tagul nav.
- Nav-ul contine o lista neordonata cu linkuri.
- Fiecare optiune principala are icon reprezentativ din Font Awesome:
  Acasa, Produse, Galerii, Servicii, Contact.
- Meniul este gandit ca element comun, care poate fi copiat pe fiecare pagina a site-ului.

2) Submeniuri
- Submeniul Acasa contine linkuri catre sectiuni din pagina curenta:
  Despre, Produse, Evenimente, Video, Contact.
- Submeniul Galerii contine linkuri catre alte pagini din site, chiar daca paginile nu exista inca:
  galerie-statica.html, galerie-dinamica.html, galerie-video.html.
- Astfel sunt acoperite ambele tipuri cerute de submeniu: sectiuni din pagina si pagini grupate descriptiv.

3) SASS si CSS compilat
- Stilizarea meniului este scrisa in resurse/css/menu.scss.
- resurse/css/menu.css este fisierul compilat din SASS si este inclus in views/pagini/index.ejs.
- Comanda folosita pentru compilare:
  npx sass resurse/css/menu.scss resurse/css/menu.css --no-source-map

4) Variabile si tema cromatica
- Informatiile care depind de tema cromatica a meniului sunt puse in variabile CSS declarate in selectorul body.
- Culorile meniului folosesc variabilele cromatice existente ale site-ului 4Pets.
- Varianta mobile are o variabila separata pentru fundalul meniului, astfel incat animatia circulara sa fie vizibila pe fundalul header-ului.
- Nu am folosit exact culorile din exemplul video, deoarece enuntul permite adaptarea cromatica.

5) Cerinte SASS
- Pentru selectori complecsi am folosit imbricarea din SASS.
- Pentru cod comun am definit placeholder-ul %link-meniu si l-am refolosit cu @extend.
- Pentru optiunile principale am folosit @for, care seteaza intarzieri progresive pentru animatia meniului pe mobil.
- Valorile repetitive sunt tinute in variabile SASS sau variabile CSS.

6) Meniu pe ecran mare
- La hover pe o optiune principala apare o bara generata prin pseudo-elementul ::after.
- Bara are background gradient cu 3 culori, coboara de sus, devine opaca si se aliniaza cu marginea de jos a butonului.
- Submeniurile se deschid prin scalare de la 0 la dimensiunea completa.
- Scalarea porneste din centrul boxului submeniului.
- La hover pe o optiune din submeniu se schimba culoarea de background.

7) Meniu pe ecran mediu
- Textul optiunilor principale este ascuns vizual.
- Raman afisate doar iconurile Font Awesome pentru optiunile principale.
- Fontul meniului este redus pentru adaptare la latimea ecranului.

8) Meniu pe ecran mic
- Optiunile principale sunt ascunse initial si se afiseaza prin hamburger menu.
- Meniul se deschide fara JavaScript, folosind checkbox + label.
- In varianta burger, prima pagina este afisata doar prin iconul casa.
- Bara glisanta de pe desktop dispare in varianta mobile.
- Comportamentul pe hover/focus devine doar schimbarea culorii de background.
- Meniul principal apare cu clip-path circular, care creste din coltul stanga-sus dupa apasarea hamburger-ului.
- Submeniurile se deschid dedesubtul optiunii parinte, iar hover/focus schimba doar culoarea de background.

9) Verificare
- Am compilat SASS in CSS cu npx sass.
- Am verificat vizual starea desktop si mobile in Chrome headless, folosind screenshot-uri locale.

COMPLETARE ETAPA 3 - Stil pentru printare
==================================================

Fisiere principale: views/pagini/index.ejs, resurse/css/style.css

Observatie:
- Bannerul cerut este implementat ca paragraf in footer, cu textul "Acesta este un proiect școlar!".

1) Banner print
- In footer exista paragraful p.banner-print cu textul cerut.
- La printare, bannerul este pozitionat jos pe prima pagina.
- Este centrat pe orizontala prin left: 15% si width: 70%.
- Are border negru inset de 4px si fundal alb pentru lizibilitate.

2) Ascundere media si elemente dependente
- La printare sunt ascunse imaginile, picture/source, video, audio, iframe, object, embed, canvas, svg.
- Sunt ascunse si figure/figcaption, containerul de iframe, taburile iframe, sectiunile de imagine, video si PDF.
- Linkul catre inceputul paginii este ascuns prin clasa link-inceput si prin selectorul #link-top.

3) Layout pentru print
- Main-ul si zona 1 trec la display: block, astfel incat gridul sa nu fie sectionat in paginile printate.
- Zonele de continut pierd background-ul, borderul, border-radius-ul si box-shadow-ul pentru un print curat.
- Tabelul este pastrat lizibil, cu border collapse si borduri negre de 1px.

4) Linkuri normale
- Toate linkurile sunt afisate ca text normal la printare.
- Culoarea este mostenita, font-weight-ul este mostenit, iar sublinierea este eliminata.

5) Header si meniu la print
- Headingul h1 ramane pe prima pagina si este centrat.
- Subtitlul din hgroup este ascuns.
- Meniul este afisat ca lista neordonata verticala.
- Submeniurile si iconurile Font Awesome ale meniului sunt ascunse.
- Dupa header/meniu se forteaza page break.

6) Footer la print
- Inaintea footerului se forteaza page break.
- Linkul catre inceputul paginii si iframe-ul Google Maps din footer sunt ascunse.

7) Watermark
- Watermark-ul este realizat prin pseudo-elementul body::after in media print.
- Contine numele pe primul rand si prenumele sub el: Pop / Matei.
- Are dimensiune 4cm x 1cm, border solid negru de 3px, colturi rotunjite, text centrat si bold.
- Este pozitionat fixed in coltul dreapta jos, cu opacity 0.4, astfel incat apare pe fiecare pagina printata.

8) Margini de pagina
- Pentru printare este folosit @page.
- Paginile din stanga au margine stanga 3cm si margine dreapta 1cm.
- Paginile din dreapta au margine dreapta 3cm si margine stanga 1cm.
- Regulile responsive pentru ecran sunt limitate cu media screen, ca sa nu modifice stilul de print.

9) Verificare
- Verificarea se face direct din browser cu Print Preview (Cmd+P / Ctrl+P).
- In preview se verifica prima pagina, page break-urile, ascunderea media, watermark-ul si marginile alternante.

- Proiectul are package.json creat cu npm init.
- Sunt setate numele proiectului, autorul, descrierea si cuvintele cheie.
- Sunt instalate dependintele express si ejs.
- Exista scriptul npm start pentru pornirea serverului cu node index.js.

2) Server Express
- In radacina proiectului exista fisierul index.js.
- Serverul Express foloseste portul 8080 implicit.
- Daca portul 8080 este ocupat, serverul incearca portul 8081.
- In consola se afiseaza __dirname, __filename si process.cwd().
- __dirname si process.cwd() nu sunt intotdeauna acelasi lucru: __dirname este folderul fisierului curent, iar process.cwd() este folderul din care a fost pornit procesul Node.

3) EJS si structura views
- View engine-ul este setat la ejs.
- Folderul views contine pagini si fragmente.
- Paginile intregi sunt in views/pagini.
- Fragmentele reutilizabile sunt in views/fragmente.
- Fisierul principal a fost redenumit in views/pagini/index.ejs.
- Head-ul comun, headerul si footerul au fost decupate in fragmente separate si incluse cu include().

4) Resurse statice
- Folderul resurse este definit static in Express.
- Resursele sunt organizate in subfoldere: resurse/css, resurse/imagini, resurse/documente si resurse/ico.
- Caile din pagini sunt scrise ca cereri catre server, de forma /resurse/....

5) Rute pentru pagini
- Pagina principala se poate accesa prin /, /index si /home.
- Exista ruta generala /*, plasata ultima, care incearca randarea paginii cerute din views/pagini.
- Pentru randare se foloseste callback-ul render(eroare, rezultatRandare).
- Daca view-ul nu exista si eroarea incepe cu "Failed to lookup view", se afiseaza pagina 404.
- Pentru alte erori se afiseaza pagina de eroare generica.

6) Sistem de erori
- Erorile sunt configurate in erori.json.
- JSON-ul contine cale_baza, eroare_default si vectorul info_erori.
- Sunt definite erorile 400, 403 si 404.
- Imaginile pentru erori sunt in resurse/imagini/erori.
- initErori() citeste JSON-ul si incarca datele in obGlobal.obErori.
- afisareEroare() primeste response-ul, identificatorul si optional titlu/text/imagine.
- Daca titlul, textul sau imaginea sunt transmise ca argument, acestea au prioritate fata de datele din JSON.
- Template-ul comun pentru erori este views/pagini/eroare.ejs.

7) Pagina noua
- A fost adaugata pagina views/pagini/istoric.ejs.
- Pagina are continut scurt despre proiectul 4Pets.
- Meniul contine link catre /istoric, deci pagina se acceseaza prin cerere GET.

8) IP utilizator
- In zona "Date utilizator si statistici" este afisat IP-ul utilizatorului.
- Local se vede de obicei ::1.

9) Restrictii speciale
- Cererile catre foldere din /resurse primesc eroarea 403 Forbidden.
- Cererile catre fisiere cu extensia .ejs primesc eroarea 400 Bad Request.
- Cererea /favicon.ico trimite fisierul favicon.ico cu sendFile().

10) Foldere generate
- Exista vectorul vect_foldere cu: temp, logs, backup, fisiere_uploadate.
- La pornirea serverului se verifica existenta fiecarui folder si se creeaza daca lipseste.
- Pentru concatenarea cailor filesystem este folosit path.join().

11) Verificare
- npm start porneste serverul.
- Rutele /, /index, /home si /istoric raspund cu 200.
- /resurse/css/ raspunde cu 403.
- /index.ejs raspunde cu 400.
- /nu-exista raspunde cu 404.
